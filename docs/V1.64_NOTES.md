# v1.64: Search fixes

## What was weird, and what changed
**App drawer search (arc)**
- Typing kept the OLD centre app in the centre (e.g. Gmail) while the best match (Gallery) sat next to it, and Enter opened the first result, not the one in the centre. Now the best match is centred whenever the text changes, and Enter opens the app that is centred (so if you scroll after typing, Enter opens what you see).
- One letter used to match anywhere inside names (typing "g" showed Messages, Banking, Settings, even contacts like "911 Emergency"). One letter now matches only the start of a name or a word.
- Loose matches (letters in order, or package name) were mixed in with real matches ("clo" listed Calculator after Clock). They now show only when no name starts with the text, so "cmr" still finds Camera but "clo" shows just Clock.

**Home search (swipe down)**
- Same one-letter and loose-match rules as the drawer.
- Actions (Settings, Focus timer, Home) matched anywhere in their name ("c" and "m" showed Focus timer / Home). They now match the start of a word ("foc", "tim", "ho", "sett" still work).
- "Settings" appeared twice when the app and the action had the same name. It now appears once.
- The calculator row showed "= = 4"; it now shows "= 4".

Changed: `app/src/web/index.src.html` and generated `assets/index.html`; `APP_VER` / `versionName` 1.64. No Kotlin change.
Checked in headless Chromium (390x844): 18 search checks plus the 29 home-grid checks from v1.63, no page errors. Not yet checked on a real phone with your real app list.
