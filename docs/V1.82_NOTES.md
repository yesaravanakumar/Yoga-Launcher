# v1.82 Build 0: Reactive Matter FX foundation

No visible effect yet. This build adds the safe base the ten effects plug into, one build at a time.

## What changed
- Engine (v60 Arc Wave script): read-only events only. `FXE('open'|'close'|'select'|'down'|'drag'|'release'|'tap'|'snap')`, plus `window.AWENG` (state, slotD, elements). `pos`, `slotD` and `paint()` are untouched; the engine never waits for FX and a throwing FX layer cannot break it.
- New script `v182-reactive-matter` (`window.AWFX`): master switch, presets, reduced motion, one shared frame ticker, cleanup, frame-rate guard.
- Arc settings has a new **FX** tab: Reactive Matter FX (master), Auto-protect, Intensity (Off / Subtle / Balanced / Experimental) and a status line. Settings keys: `fxOn`, `fxLevel`, `fxAuto` (default on / Subtle / on). Per-effect switches will be `fx_<name>`.

## Rules the core enforces
- Layers register with `AWFX.layer(id,{min,rm,keep,on:{...},stop})`. `min` is the lowest level (1 to 3) that runs it; `rm:true` means it has a static reduced-motion version, otherwise it does not run under reduced motion.
- A new touch (`down`) stops running layers first; closing the drawer, hiding the page, reduced motion or turning FX off settles everything.
- `AWFX.tick(fn)` is the only frame loop. It starts when an effect asks and ends when all tasks return false. No permanent loop, glow or particle system.
- Inline styles a layer puts on icons are recorded with `AWFX.mark(el,prop)` and reset on settle. Layers move icons with the individual `translate` property, never `scale` and never the drawer's `transform` string.
- Colours come from `--c1` / `--c1rgb` only.
- Frame guard: during FX frames it averages 24 frames; two slow windows in a row (over about 26 ms) lower the level one step (Experimental, Balanced, Subtle, Off). The result is remembered for the chosen preset; picking a preset again or tapping Re-test clears it. Minimal mode turns FX off. Performance mode is set automatically on Android, so it does not cap the preset.

## Tests added (tools/smoke)
- `fx-core-test.js` (jsdom, 31 checks): presets, master switch, level gating, per-effect switch, gesture cancel, ticker ends by itself, close settles, style restore, throwing layer, frame guard, reduced motion, FX tab.
- `fx-events-test.py` (Chromium, real touch events): engine events fire.
- `fx-layout-test.py` (Chromium): 320x570, 360x740, 390x844, 412x915 in Arc, Orbit, Wave and Fan; engine geometry identical with FX Off and Experimental; selected name clear of the A-Z strip.
Run: `cd tools/smoke && npm install && node fx-core-test.js && python3 fx-events-test.py && python3 fx-layout-test.py`.
Existing checks (check2, check5, hold-test, check.js) fail the same way on v1.81; unchanged by this build.

Not tested on a physical device: frame rate on phones, haptics.

# v1.82 Build 1: Liquid touch ripple (`fx_ripple`)
- Layer `v182-fx-ripple`, min level Subtle, has a reduced-motion fallback. FX tab: "Liquid touch ripple" switch.
- Press and hold on the wave (70 ms): a thin `--c1` ring spreads from the finger and nearby icons are nudged by a decaying travelling wave (`translate`, up to about 4 px at Subtle, 7 px at Experimental). About half a second, then everything is put back.
- Quick taps and swipes never show it: a drag, a release, a selection change, the app's own hold-to-drag, closing the drawer or the next touch cancels it immediately.
- The selected icon is never moved; drawer `transform` strings are untouched; no `scale` property used. Reduced motion: still ring that only fades, no icon movement.
- Tests: `fx-ripple-test.py` (54 checks at the four sizes) and `fx-ripple-compat-test.py` (13 checks: long-press menu, A-Z jump, search, labels, tap to open, FX Off vs Experimental).
- Core change: `AWFX.mark` now de-duplicates per element (no growth during long effects).

# v1.82 Build 2: Magnetic selection (`fx_magnet`)
- Layer `v182-fx-magnet`, min level Subtle, no reduced-motion version (it does not run under reduced motion). FX tab: "Magnetic selection" switch (default on).
- When the selected app changes, nearby icons lean toward the selected icon for about 0.45 s (soft attack, a small rebound outward, then rest). Up to about 5 px at Balanced, about 6 px at Experimental, Subtle is lighter. Reach is about 38% of the drawer height, with a soft falloff.
- Individual `translate` only: `pos`, `slot()`, `paint()` and the drawer's transform strings are untouched; no `scale`; the selected icon is never moved. The opening cascade (first 650 ms after open) is ignored; fast scrolling keeps one running pulse instead of stacking; the next touch, drag-start, closing the drawer, FX Off or the per-effect switch cancels it at once. Elements it moves are recorded with `AWFX.mark` and reset on settle.
- Tests: `fx-magnet-test.py` (53 checks at 320x570, 360x740, 390x844, 412x915 + reduced motion), `fx-smoke-chromium.py` (6 checks; stand-in smoke-load for machines without jsdom).
- Test-harness fix: `fx-layout-test.py` now waits for the glide to settle before comparing geometry (it sampled mid-glide and failed intermittently on v1.82 too).

# v1.82 Build 3: Holographic snap (`fx_holo`)
- Layer `v182-fx-holo` (+ small stylesheet `v182-fx-holo-css`), min level Subtle, has a reduced-motion version. FX tab: "Holographic snap" switch (default on).
- When the wave snaps onto an app (A-Z jump, tap-to-select, keys, wheel, release after a slow swipe) or settles after a fast fling, a thin `--c1` frame assembles around the selected icon: four rounded corner brackets slide in from slightly outside (about 0.26 s), a hairline joins them (Balanced and Experimental), the frame holds briefly and fades. About 0.86 s in total, then the elements are removed.
- Intensity: Subtle = corners only, short travel. Balanced = corners + hairline. Experimental = longer travel and a soft corner glow. Reduced motion = the same frame fades in and out with no movement.
- Event-driven: the layer waits (up to 1.1 s, 2.6 s after a fling) until the wave is close to rest, so nothing flashes during a swipe. A new touch, a drag, closing or re-opening the drawer, selecting another app while it shows, FX Off, or the per-effect switch removes it at once. Repeated snaps never stack frames.
- Overlay only (in the `#awFx` host): it does not touch icons, `pos`, `slot()`, `paint()` or any transform string. Colours come from `--c1` / `--c1rgb` in the stylesheet; no hardcoded palette.
- Readability: the frame follows the engine's layout position of the icon (not its pop animation). Only the side facing the selected name is pulled in (below it in Arc and Wave, beside it in Orbit, above it in Fan), so the frame can graze the name's padding by at most 2 px and never reaches the text. It never reaches the A-Z strip (right edge, left edge in Fan).
- Tests: `fx-holo-test.py` (253 checks: Arc, Orbit, Wave and Fan at 320x570, 360x740, 390x844 and 412x915; the full battery runs on Arc 320 and 390: Subtle/Balanced/Experimental differences, real-touch cancel, real fast swipe, re-select, close mid-effect, open, A-Z jump, switch off, reduced motion). `fx-smoke-chromium.py` now also expects the `holo` layer.

# v1.82 Build 4: Energy trace (`fx_trace`)
- Layer `v182-fx-trace` (+ stylesheet `v182-fx-trace-css`), min level Subtle, no reduced-motion version (does not run under reduced motion). FX tab: "Energy trace" switch (default on).
- Starts only on a fast swipe (finger speed at least 4.2 steps/s) or a fling. A short row of soft `--c1` dots is laid along the wave path behind the selected slot; longer and brighter the faster the gesture. Subtle 4 dots, Balanced 6, Experimental 8 with a soft glow.
- Fades by itself when the speed drops (a stalled finger counts as stopped after 90 ms); hard cap 3.2 s. The next touch, closing the drawer, the per-effect switch, FX Off or the Off preset removes it at once. Never stacks, no permanent loop.
- Overlay only (`#awFx`): one transform string and opacity per dot. It never touches icons, `pos`, `slot()`, `paint()` or the drawer's transform. Dots that would land on the selected icon, the selected name or the A-Z strip are hidden.
- Tests: `fx-trace-test.py` (236 checks over Arc, Orbit, Wave, Fan at 320x570, 360x740, 390x844, 412x915; full battery on Arc 320 and 390). Run one design at a time (`TR_DES=wave python3 fx-trace-test.py`); running several in parallel starves the headless browser and gives false failures. In Wave the swipe starts at x=.15W because the star/home/edit buttons sit at x=.3W.
- Also passing: fx-core-test.js 31/31, smoke-load.js 0 errors, e2e.js 28/28, fx-smoke-chromium 7/7, fx-events-test 7/7, fx-layout-test 68/68, minified build loads and passes the trace test.
- Intermittent, also on the unmodified v1.82 build: fx-magnet-test "small rebound away from it before settling" (1 failure in about 1 run in 2 on both). Not rerun this build: fx-holo-test, fx-ripple tests.
- Not tested on a physical device: frame rate on phones, haptics.

# v1.82 Build 5: Prism edges (`fx_prism`)
- Layer `v182-fx-prism` (+ stylesheet `v182-fx-prism-css`), min level Subtle, has a reduced-motion version. FX tab: "Prism edges" switch (default on).
- When the wave settles on an app (same arming as Holographic snap: snap, tap-select, A-Z jump, release after a slow swipe, settle after a fling), a thin `--c1` reflection travels once around the selected icon's rim (a crescent that rotates about 160 to 200 degrees) in about 0.8 s, then removes itself. Nothing shows during a swipe.
- Intensity: Subtle = one crescent. Balanced = crescent + a paler fringe on the opposite side (`--c1` mixed toward white where `color-mix` exists). Experimental = adds a faint outer glow. Reduced motion = the same rim light fades in and out without travelling.
- Overlay only (`<b>` elements in `#awFx`, so ripple/holo selectors on `i` are unaffected): it never touches icons, `pos`, `slot()`, `paint()` or any transform string; no `scale` property. Inset shadows, no mask, no fill, so it cannot cover the icon face. It follows the icon's live rect (shell scale, pop and float included) for those 0.8 s only. A new touch, a drag, closing or re-opening the drawer, selecting another app, FX Off or the switch removes it at once. Never stacks; no permanent loop.
- Two bugs found while building it (both covered by `fx-prism-test.py`): (1) sizing the ring once at build time put it on a smaller, offset square because the icon is still mid-pop; (2) an outer `box-shadow` on the container darkened the icon face in Chromium, so the Experimental glow lives on its own child (`.po`).
- Tests: `fx-prism-test.py` (Arc 114, Orbit/Wave/Fan 83 each, at 320x570, 360x740, 390x844, 412x915; includes a pixel brightness regression for the icon face and the reduced-motion case). `PR_DES=wave python3 fx-prism-test.py` runs one design. Also passing: fx-core-test.js 32/32, smoke-load 0 errors, e2e 28/28, fx-smoke-chromium 8/8, fx-events-test 7/7, fx-layout-test 68/68, fx-ripple-compat-test 13/13, fx-magnet-test 53/53; the minified build passes fx-prism-test (Arc, 114/114).
- Known test status: `fx-ripple-test` "drag cancels" (2 to 3 failures per run at random sizes) and `fx-holo-test` "no frame while the finger is still dragging" (Arc 320 and 390) fail the same way on the unmodified Build 4, so they are not caused by this build. fx-holo-test was run on Arc only; Orbit, Wave and Fan were not rerun.
- Not tested on a physical device: frame rate on phones, haptics.
