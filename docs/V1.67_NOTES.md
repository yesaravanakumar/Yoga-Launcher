# v1.67: free placement of icons and widgets on the home screen

## Icons: drop them anywhere
- Edit home > **Grid** > **Free placement (drop icons anywhere, no grid)**. Off by default, so nothing changes until you switch it on.
- With it on, hold an app on the home screen (or from the drawer), drag, and it lands exactly where you let go. The dashed cells are not shown. Dock slots, page dots and "drop to remove" work as before.
- An icon cannot be dropped under the clock or date. It is kept on screen and above the dock.
- Icons you already placed in cells stay where they are. Cell icons and free icons can be mixed. Turning the switch off only affects new drops.
- Saved per home page, in the same `mdc-hpos` store (new `fx`, `fy` fields).

## Widgets: put them on the home screen
- **Widgets page > Pin to home** on any widget or stack. The page closes and arrange mode starts.
- **Arrange mode** (also: hold empty space > Edit home > Widgets > **Arrange home widgets**): drag a widget anywhere, pull the round corner handle to resize, ‹ › flip through a stack, ✕ takes it off the home screen, **Add** picks a new widget and pins it. **Done** (or Esc) finishes. Real Android widgets are hidden while you arrange, so you drag a dashed placeholder, then the real widget returns on Done.
- A pinned widget belongs to the home page it was pinned on and shows only there. It hides when the drawer, Settings, search, menus, the Widgets page, the clock layout mode or the lock screen are on top.
- Still on the Widgets page too: grip resize, S/M/L, Stack, Unpin.
- No Kotlin change: the existing placeWidget / hideWidget calls take any position.

## Limits
- A real Android widget is a native view drawn above the page, so an icon dropped on top of a widget cannot be tapped. Move one of them.
- Widget height and width are free, but each widget app decides how small it can really draw.
- Locked home layout (Settings) blocks arrange mode and drag, as before.
- Checked in headless jsdom (tools/smoke/edit-test.js, 35 checks, no page errors). Not yet tried on a real phone, and the real widget following the drag has not been seen.
